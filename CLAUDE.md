# PowerPoint Dojo : notes pour Claude

Add-in PowerPoint (Office.js) d'entraînement, en français, jumeau de l'Excel Dojo (Julomasu/excel-dojo). Le propriétaire (Jules, stagiaire M&A, débutant en code) travaille sur Mac ET sur un Windows sans droits administrateur : il demande les changements à Claude, il n'installe rien en local. Dépôt **public** : jamais de secret (jamais de clé Supabase `service_role`).

## Fonctionnement
- Site statique Vite + JS vanille (`src/`), affiché comme volet d'add-in dans PowerPoint, ou comme page web (« mode fichier » : téléchargement d'un .pptx, dépôt pour correction).
- En ligne : **https://slidesdojo.vercel.app** (projet Vercel `slidesdojo`, adresse définitive : `HOSTED_URL` dans `src/manifest.js`). **Un push sur `main` redéploie la production.** Ne fusionner que sur demande explicite.
- `/install` génère le `manifest.xml` (`src/manifest.js`). **Ne jamais changer** `HOSTED_ID` ni l'adresse du site une fois publiés.
- **Manifests du dépôt** : `manifest.local.xml` (test, `localhost:3000`, identifiant de TEST) et `manifest.prod.xml` (en ligne), générés par `npm run manifests`. Ne PAS les confondre : en installant le manifest local par erreur, l'add-in apparaît mais sans logo et le volet ne s'ouvre pas (diagnostiqué chez Jules le 2026-11-10).
- **Installation Windows validée (Jules, sans droits administrateur)** : le menu « Charger mon complément » n'existe pas dans sa version ; ce qui marche = déclarer le manifest dans le registre `HKCU:\Software\Microsoft\Office\16.0\WEF\Developer` (nom = `HOSTED_ID`, valeur = chemin du manifest), puis redémarrer PowerPoint → Accueil → Compléments → « Developer Add-ins ». La page `/install` génère une commande PowerShell qui contient le manifest (dossier `%USERPROFILE%\PowerPointDojo`, distinct de celui d'Excel). Vider le cache après une mise à jour : `%LOCALAPPDATA%\Microsoft\Office\16.0\Wef`. Mac : dossier `~/Library/Containers/com.microsoft.Powerpoint/Data/Documents/wef` (non testé).
- Branche de travail lot 1 : `claude/powerpoint-dojo-lot1`.

## Architecture (idée centrale)
Un **modèle de présentation** (`src/deck.js`, unités en points, 960×540 = 16:9) et des **opérations JSON** (`slide`, `add`, `set`, `del`, `delSlide`, `dupSlide`, `moveSlide`, `layout`, `bg`, `size`, `group`, `ungroup`, `z`, `notes`, `hide`) :
- `setup` (départ) et `sol` (solution) d'un exercice sont des listes d'opérations ;
- jouées en JS pur par `npm run verify` (`runOps`), dans le vrai PowerPoint par `src/ppt.js` (`applyOps`, `loadSetup`), écrites en .pptx par `src/pptx.js` ;
- le correcteur (`src/grader.js`, contrôles de `src/answers.js`) ne voit que le modèle, produit par `readDeck()` (PowerPoint) ou `readPptx()` (mode fichier).
- **Règle d'or** : une propriété illisible dans une version = `undefined` dans le modèle = **ignorée** (jamais bloquante). Un contrôle entièrement ignoré s'affiche « non vérifiable ».
- Contrôles : `transitionA`, `noTransitionA`, `animA`, `shapeA` (valeur `{exact}` pour la casse, `{min,max}`, `{approx,tol}`, `{near}`, `{oneOf}`), `countA`, `slidesA`, `layoutA`, `bgA`, `sizeA`, `alignA`, `distributeA`, `ruleA`, `noOverlapA`, `insideA`, `contrastA`, `confirmA`. Sélecteurs de forme : `"Nom"`, `{name, ph, text, kind, group, idx, nth}`.
- Fichiers : `xml.js` (mini lecteur XML), `pptx.js`, `ppt.js`, `caps.js` (jeux PowerPointApi 1.1→1.10, `requirementsOf`), `profile.js`, `diagnostic.js`, `validate.js`, `skills.js` (GROUPS/SKILLS), `skilllessons.js`, `keys.js`, `preview.js` (aperçu SVG), `progress.js` + `cloud.js` + `config.js` (comme l'Excel Dojo), `main.js` (UI), `tracks/*.js` (exercices).

## Ce que l'API PowerPoint permet (d'après learn.microsoft.com, PowerPointApi 1.1→1.10)
**Lu et écrit pour de vrai** : diapositives (ajout, suppression, déplacement 1.8, mise en page par `applyLayout` 1.8, lecture `layout`), formes (nom, position, taille, remplissage, contour, texte, police, alignements, type) 1.4 ; groupes, ordre Z, tableaux (valeurs) 1.8 ; arrière-plan, taille des diapositives, texte alternatif, rotation, couleurs du thème 1.10 ; liens 1.5/1.10 ; export d'une diapositive en base64 (`exportAsBase64`, 1.8).
**Non exposé** (à confirmer par l'élève via `confirmA`, ou à lire dans le XML d'`exportAsBase64` avec `xml.js` + JSZip — prévu aux lots suivants) : animations, transitions, SmartArt (type lisible seulement), médias, morph, mode diaporama, notes, diapositives masquées, géométrie précise d'une forme (rectangle/ellipse : `kind:"shape"` lu, les sélecteurs `kind` sont donc permissifs), sections.
**Dépend de la version** : tout ce qui est marqué 1.8/1.10 ; `requirementsOf` déduit la version d'un exercice, `compatible()` masque les exercices non corrigeables.
**⚠ Rien n'a pu être testé dans un vrai PowerPoint** (pas disponible ici) : `ppt.js` (lecture/écriture Office.js), la détection de mise en page par type de `SlideLayout`, la balise `PPTDOJO`, et l'ouverture des .pptx générés dans PowerPoint (testé seulement avec LibreOffice). **Jules doit lancer Moi → Diagnostic de ton PowerPoint puis « Contrôle qualité »** sur Mac et Windows, et rapporter les lignes en échec.
- Sécurité : le Dojo **remplace tout le contenu de la présentation ouverte** à chaque exercice. Une présentation non marquée et non vide déclenche une demande de confirmation. Le Diagnostic, lui, n'ajoute que des diapositives temporaires.

## Écrire un exercice
`mk({ id, skill, level, xp, title, story, setup:[ops], answers:[contrôles], sol:[ops], steps:[pistes], hint })` dans `src/tracks/*.js`, puis l'ajouter à `src/exercises.js`. Valeurs attendues **calculées en JS**. Ne jamais renommer un `id` publié. `steps` = Piste (−10 %), `hint` = Indice (−30 %), Solution = 0 XP (écrit la solution dans la présentation). Utiliser `{{Windows|Mac}}` pour les raccourcis (`K` dans `keys.js`). Chaque exercice doit : ne pas être réussi au départ, être réussi après `sol`, survivre à un aller-retour .pptx.

## Vérifier avant de pousser
`npm install`, `npm run verify` (départ ≠ réussi, solution réussie, aller-retour .pptx, ids uniques), `npm run build`. Aperçu local : `DOJO_HTTP=1 npm run dev`. `npm run icons` / `node scripts/make-manifest.mjs` (manifest de test local).

## Plan par lots
1. ✅ Squelette, manifest, install, diagnostic, chapitre « Les bases » (31 exercices), mode fichier, progression locale, compte (config vide).
2. ✅ Test pour sauter un chapitre (`grp:<id>` : 4 épreuves tirées dans le chapitre, 3 à réussir, 5 min chacune, sans aide ; réussi = `recordSkip`, tous ses exercices comptent faits via `doneMap()` sans XP) et test de niveau (`src/placement.js`, 12 questions « bases » pour l'instant ; chaque nouveau chapitre ajoute ses questions, cible ≈ 24 ; les chapitres tout juste proposent d'être sautés). Pas de test pour sauter une « ceinture » : le parcours PowerPoint n'a que des chapitres.
3. 🟡 Ruban (en cours) : Accueil (42), Insertion (27), Création/Transitions/Animations (≈24), Diaporama/Révision/Affichage (≈23) = ≈110 exercices en `tracks/ruban-*.js`. **Transitions/animations lues dans le XML** de `slide.exportAsBase64()` (JSZip + `slideExtras()` dans `pptx.js`) : `transitionA`, `animA`, flag `xml` déduit par `requirementsOf` ; cibles d'animation retrouvées par NOM de forme. Les ops `transition`/`anim` ne s'écrivent PAS dans PowerPoint : un exercice dont le **départ** en contient (`unwritable`) est masqué dans l'add-in et reste jouable en mode fichier (transitions seulement : le .pptx généré n'écrit pas les animations). Reste : masque des diapositives, hiérarchie de mise en page, plus d'exercices de mise en forme avancée pour atteindre ≈150.
4. ✅ Certification (`src/certif/`) : examen noté sur 100 (100 = champion du monde de PowerPoint). **Aucune banque fixe d'énoncés** : `gen1.js` (niveaux 1-3) et `gen2.js` (niveaux 4-5) = **50 générateurs** ; chaque `make(g)` tire contenus, couleurs, nombres, positions et consignes d'une graine (`kit.js` : `rnd`, `POOLS`, `COLORS`) et recalcule les attentes en JS. 7 domaines (`CATS`) : Diapositives et texte, Formes et couleurs, Mise en page et alignement, Design et lisibilité, Tableaux et objets, Ruban et réglages, Cas de métier (football field, bridge, teaser, strip profile, timeline, organigramme, grille, mini-deck). `generate(genId, seed)` = exercice ordinaire (id `cx~gen~graine`), rejouable pour la correction. `drawExam(kind)` : complète (20 épreuves, 90 min, quotas `[5,5,4,3,3]`) ou express (10, 40 min), domaines variés, épreuves incompatibles avec la version de PowerPoint écartées. Score = Σ(poids du niveau × part de contrôles réussis) / Σ poids × 100 (`scoreOf`), paliers `BANDS`, détail par domaine, corrections à la fin, historique dans `progress.certs`. Pendant l'examen : ni piste, ni indice, ni solution, pas de correction en direct (bouton « Valider cette épreuve », on peut passer et revenir). `CERT_SEEDS=150 npm run verify` teste 150 tirages de chaque générateur (4 par défaut) : départ non réussi, solution réussie, aller-retour .pptx. Nouveau générateur : l'ajouter à `GEN1`/`GEN2`, lancer verify avec beaucoup de graines (les jitters aléatoires peuvent produire un départ déjà bon).
5. Comptes : activer Supabase (`supabase/schema.sql`, table `pptdojo_progress`) — **demander à Jules l'URL et la clé publishable**.
6. 🟡 Fait : chapitre **Design** (`tracks/design.js`, 18 exercices : un message par slide, hiérarchie/contraste, grille/marges), **Cas de métier** (`tracks/metiers.js`, 25 : football field, bridge, comparables avec multiples/médiane/moyenne calculés, sensibilité, teaser, anonymisation, one-pager, strip profile, sources et emplois, capital, timeline à l'échelle, organigramme, matrice 2×2, entonnoir, KPI, effectifs), **Sans Microsoft 365** (`tracks/sans365.js`, 15 : fonctions récentes confirmées + alternatives qui marchent partout). Badges `365` / `2019+` via la table `TIER` de `exercises.js` (+ bouton « je n'ai pas cette fonction : passer » qui valide à 0 XP) ; le Dojo ne sait pas détecter Designer/Morphose par l'API : l'avertissement « PowerPoint ancien » se base sur la version PowerPointApi (< 1.5). Test de niveau : 18 questions (bases, ruban Accueil, design). **Total : 197 exercices** ; reste à faire pour 500+ : chapitres Graphiques/tableaux, Masque/modèles (hiérarchie de mise en page), plus de cas de métier (conseil, finance, marketing, RH, ventes), plus de ruban avancé.
